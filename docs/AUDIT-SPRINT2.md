## 4. Known-gap register: §14.6(h) partial-overlap DST skip

**Code implements the ratified stricter reading.** [`computeSlots`](../src/lib/slots/engine.ts:119) skips a window if **either** endpoint wall time is nonexistent (`windowStart === null || windowEnd === null → continue`), via the round-trip check in [`wallToUtc`](../src/lib/slots/engine.ts:55) (Luxon forward-maps skipped times, so components come back shifted → detected and rejected). [`materializeWorkingWindows`](../src/lib/slots/engine.ts:163) applies the identical rule. A 02:30–03:30 window on 2027-03-28 Helsinki (existing start, nonexistent end) yields zero slots and zero windows — no clamp, no phantom mapping.

**Spec coverage:** only the both-endpoints-nonexistent case is pinned ([engine.test.ts](../tests/slots/engine.test.ts:377)). Partial overlap is implemented-but-untested — exactly what §14.6(h) flagged to this audit.

**Risk: LOW.** [CONF: MED] [SRC: INFERENCE] Helsinki spring-forward is 03:00→04:00 local; salon hours touching it require working_hours starting in 02:xx–03:xx — atypical. Failure direction is conservative: skipping suppresses slots (lost availability for one exotic day), never phantom slots or double-booking. Create-path and offer-path share the rule, so no STALE_SLOT divergence is possible.

**Disposition: TASK-201c micro-task, not TASK-301.** One pure 15-line spec (window 02:30–03:30 on 2027-03-28 → 0 slots), no DB, no dependencies. TASK-301 is landing-page UI with zero slot-engine cohesion — deferring there misplaces the spec. Adjacent unspecced edge to pin in the same micro-task: a fall-back window wholly inside the repeated hour collapses to the earlier occurrence (Luxon default) — conservative, currently unpinned.
